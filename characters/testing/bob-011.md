## How the earlier NSFW block was resolved

`bob-007.md` documents the original prompt failing with `3030: Input
prompt contains NSFW content.` on `phoenix-1.0`. This model turned out to
be much stricter than `lucid-origin` (see `bob-010.md`):

- The **original, unmodified** prompt was retried **18 times in a row** and
  failed all 18 with the identical `3030` error — much worse than
  `lucid-origin`'s 1-in-5 failure rate on the same text, so for this model
  the block is effectively (if not literally) content-driven, not just
  random flakiness.
- Dropping "anime" for "cartoon" and removing "57-year-old"/"crazy" (age +
  intensity descriptors) got a **clean result on the very first retry**,
  but that version had also dropped the explicit full-body/no-portrait
  framing instruction, so it came back as a head-and-torso portrait crop
  — not a match for this project's "complete person" requirement.
- Re-adding the full-body framing instructions (explicitly listing head,
  torso, arms, legs, feet; "not a portrait"; "standing in a neutral pose")
  while keeping the softened description succeeded on the **2nd** attempt
  and produced a correct full-body image (all limbs and shoes visible).

**Conclusion:** for `phoenix-1.0`, both levers mattered — softening
"anime"/"57-year-old"/"crazy" measurably reduced the false-positive rate
compared to the original wording, and retrying still played a role (2
attempts, not guaranteed on the first). `lucid-origin` needed only a retry;
`phoenix-1.0` needed the reworded prompt *and* a retry.
